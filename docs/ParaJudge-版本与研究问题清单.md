# ParaJudge 系统版本规格与研究问题清单

> 本文档定义 ParaJudge 的版本编号系统、需要通过实验验证的研究问题及其测试参数。

---

## 一、版本编号规范

### 1.1 版本格式

采用 **Semantic Versioning 3 位编号**：`主版本.次版本.修订版本`

```
v{Major}.{Minor}.{Patch}
```

| 维度 | 定义 | 触发条件 |
|------|------|---------|
| **Major（大版本）** | 架构重构、API 破坏性变更、目标用户群变更 | 新增核心模块（如 LangGraph 重构）、协议变更 |
| **Minor（次版本）** | 新功能上线、现有功能增强 | 新增 Phase（如主持人角色）、新法官类型、新评估维度 |
| **Patch（补丁版本）** | Bug 修复、文档完善、测试覆盖增强 | 不改变功能行为的修复 |

### 1.2 当前原型机版本

```
当前版本：v0.1.0
代号：Prototype-Alpha（原型阿尔法）
含义：
  - v0 = 尚未达到生产就绪（MVP 阶段）
  - 1  = 完成了 Phase 0-2 全流程可运行
  - 0  = 初始发布，无补丁
```

### 1.3 版本演进路线图

| 版本 | 代号 | 目标 | 关键里程碑 |
|------|------|------|-----------|
| **v0.1.0** | Prototype-Alpha | MVP 可运行 | 4 模块 + CLI + pytest 65 passing |
| **v0.2.0** | Prototype-Beta | 主持人角色 + 真实 LLM | Moderator agent、多轮辩论控制 |
| **v0.3.0** | Prototype-Gamma | T1 AEBG 图论评估 | PageRank + 度中心性 |
| **v0.4.0** | Prototype-Delta | T2 DPP 多样性约束 | 拒绝采样 / DPP |
| **v0.5.0** | Prototype-Epsilon | T3 KS 收敛检测 | 自适应轮数 |
| **v1.0.0** | Production-Release | 生产就绪 | T4 DS 证据融合、Web UI、T1-T3 全部集成 |
| **v1.1.0+** | Evolution | 持续迭代 | 期刊论文发表数据、多语言支持 |

### 1.4 版本间兼容性

- **v0.x 系列内部**：CLI 参数可能变化，不保证向后兼容
- **v1.0+**：Minor/Patch 版本保证 API 兼容

## 二、需要通过实验验证的研究问题

### 2.1 研究问题总览

ParaJudge 是一个**多智能体辩论评估系统**，其核心价值在于：
> **能否用 AI 多智能体辩论替代或辅助人类专家评审科研项目？**

围绕这个核心问题，拆解为以下 6 个子研究方向：

---

### RQ1：辩论质量评估 — LLM 辩论是否产生有意义的论点？

**假设（H1）**：LLM 辩论产生的论点质量（基于 AEBG 图论指标）随辩论轮数增加而提升，并在 3-5 轮后趋于稳定。

**验证方法**：
- 控制实验：同一问题，分别运行 1/2/3/5 轮辩论
- 评估指标：论点数量、正反方引用覆盖率（Citation Coverage Rate = 有证据引用的论点 / 总论点）、PageRank 分布均衡度
- 真实数据：使用 `arXiv CS.AI` 分类下的 50 个研究问题

**实验参数**：

| 参数 | 取值范围 | 步长 | 固定参数 |
|------|---------|------|---------|
| 辩论轮数（rounds） | 1, 2, 3, 5 | — | max_evidence=20, provider=dashscope |
| 证据包上限 | 10, 20, 30 | 10 | rounds=3 |
| 话题类型 | 理工类 / 社科类 / 跨学科 | — | rounds=3, max_evidence=20 |

**预期输出**：
- 折线图：轮数 → 引用覆盖率（期望：1→2→3 轮上升，>3 轮趋平）
- 箱线图：各轮次正反方 PageRank 分布差异

---

### RQ2：裁决一致性 — 5 位法官的评分是否稳定可靠？

**假设（H2）**：在相同辩论记录下，5 位法官的评分标准差 < 10 分，且与人类专家评审的结论一致性（Cohen's Kappa）> 0.6。

**验证方法**：
- 重播实验：对同一辩论记录，让 5 位法官独立评分 3 次（间隔 1 周）
- 对比实验：人类专家（3 名副教授）对同一批辩论进行独立评分

**实验参数**：

| 参数 | 取值范围 | 测量指标 |
|------|---------|---------|
| 法官类型 | evidence / logic / principle / case / innovation（5 种） | 评分分布 |
| LLM 模型 | qwen-max / gpt-4o / gpt-4o-mini | 评分一致性 |
| 评分温度 | 0.3, 0.7, 1.2 | 评分方差 |

**真实数据要求**：
- 至少 30 个不同问题的辩论记录（从 arXiv 真实检索）
- 人类专家评分来自 3 名具有副教授及以上职称的学者

**预期输出**：
- 表格：各法官类型评分均值 ± 标准差
- Cohen's Kappa 矩阵：5 位 AI 法官 vs 3 位人类专家

---

### RQ3：证据包质量 — 检索来源对辩论质量的影响？

**假设（H3）**：使用多源检索（arXiv + Crossref + Semantic Scholar）的证据包，比单一来源产生的论点引用覆盖率提升 ≥ 20%。

**验证方法**：
- 控制变量：固定问题（从预设题库抽取）、辩论轮数（3 轮）
- 自变量：检索来源组合

**实验参数**：

| 来源组合 | 来源数 | 预期引用覆盖率（估算） |
|---------|--------|------------------|
| 仅 arXiv | 1 | ~45% |
| arXiv + Crossref | 2 | ~60% |
| 三源全开 | 3 | ~75% |

**数据来源**（真实）：
- arXiv API：`http://export.arxiv.org/api/query`
- Crossref API：`https://api.crossref.org/works`
- Semantic Scholar API：`https://api.semanticscholar.org/graph/v1`

---

### RQ4：收敛检测 — KS 检验能否准确判断辩论收敛？

**假设（H4）**：使用 Kolmogorov-Smirnov 检验（α=0.05）判断 5 位法官评分分布，可在平均 3.2 轮时提前终止辩论（节省 37.5% 轮次）。

**验证方法**：
- 固定辩论至 8 轮，每轮记录 5 位法官的实时评分
- 对每轮评分序列进行 KS 检验，判断何时分布稳定
- 对比：手动设定 3 轮 vs KS 自适应

**实验参数**：

| 参数 | 取值 | 说明 |
|------|------|------|
| KS 检验显著性水平 α | 0.01, 0.05, 0.10 | 默认用 0.05 |
| 相邻轮次间距 | 1 轮 | 即每轮做一次 KS |
| 收敛判定标准 | KS-stat < α 临界值，连续 2 次 | 避免噪声误触发 |

**真实数据要求**：50 个不同问题的 8 轮完整辩论记录

---

### RQ5：DS 证据融合 vs 加权平均 — 哪种裁决更符合直觉？

**假设（H5）**：Dempster-Shafer 融合输出的不确定性区间，在人类可理解性测试中得分（1-5 Likert 量表）高于简单加权平均。

**验证方法**：
- 用户研究：招募 20 名计算机科学研究生
- 展示同一辩论的两种裁决（DS vs 加权平均）
- 问卷：哪份裁决更有说服力？为什么？

**测量指标**：
- 偏好率（DS 被选为"更有说服力"的比例）
- 不确定性标注的可理解性（1-5 分）
- 关键论点识别准确率

---

### RQ6：端到端用户满意度 — 真实用户如何使用系统？

**假设（H6）**：用户（研究生/研究员）对 ParaJudge 裁决书的可用性（System Usability Scale，SUS）得分 > 68（行业平均水平）。

**验证方法**：
- 用户研究：招募 30 名真实用户
- 任务：使用 ParaJudge 评估 3 个真实科研项目
- 测量：SUS 量表（10 题）、任务完成时间、错误率

## 三、测试实验参数汇总表

### 3.1 系统级参数

| 参数名 | 默认值 | 可选值 | 说明 |
|--------|--------|--------|------|
| `rounds` | 3 | 1, 2, 3, 5, 8 | 辩论轮数 |
| `max_evidence` | 20 | 5, 10, 20, 30 | 证据包条数上限 |
| `temperature` | 0.7 | 0.3, 0.7, 1.2 | LLM 采样温度 |
| `provider` | mock | mock, openai, dashscope | LLM 提供商 |
| `model` | mock-model | qwen-max, gpt-4o | 具体模型 |
| `enable_llm_review` | True | True / False | 是否启用 LLM 审理 |

### 3.2 评估指标体系

| 指标 | 公式/定义 | 目标值 | RQ 关联 |
|------|---------|--------|--------|
| **引用覆盖率（CCR）** | 有引用的论点 / 总论点 × 100% | > 70% | RQ1 |
| **评分一致性（Cohen's κ）** | κ = (P_o - P_e) / (1 - P_e) | > 0.6 | RQ2 |
| **收敛提前率** | (固定轮数 - 实际轮数) / 固定轮数 × 100% | > 30% | RQ4 |
| **SUS 可用性得分** | 标准 SUS 量表 10 题求和 × 2.5 | > 68 | RQ6 |
| **DS 偏好率** | 选 DS 的用户 / 总用户 × 100% | > 50% | RQ5 |

| 4 | 大模型是否会导致信息茧房加剧？ | AI+传播学 | 中 |
| 5 | 自动驾驶能否在复杂城市环境完全落地？ | 自动驾驶 | 高 |
| ... | （其余 25 题见题库文件） | | |

**人类专家评审团（3 人）**：
- 副教授 × 3（计算机科学相关方向）
- 每人独立评审所有 30 题的辩论裁决
- 独立给出"正方胜/反方胜/平局"判断

## 五、风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| LLM API 成本超支 | 中 | 高 | 使用 DashScope 预付费，设置每日调用上限 |
| 人类专家评审招募困难 | 低 | 高 | 联系导师实验室，承诺论文致谢 |
| 证据检索网络超时 | 中 | 中 | 实现本地缓存（SQLite）+ 重试机制（3 次） |
| 辩论结果与专家判断分歧大 | 中 | 中 | 扩大评审团至 5 人，取多数票 |
| 动画前端开发周期长 | 高 | 中 | 先交付低保真原型确认风格，再迭代高保真 |
