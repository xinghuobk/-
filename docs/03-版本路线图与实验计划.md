## 二、需要测试研究的问题与参数

### 2.1 核心研究问题（Research Questions）

| 编号 | 问题 | 实验方法 | 成功指标 |
|------|------|---------|---------|
| **RQ-1** | 辩论轮数 `R` 对裁决结论稳定性的影响 | 固定 3 个问题 × 每问题 5 次重复，测试 R=1/2/3/5/8 | `R ≥ 3` 时胜负一致率 > 80% |
| **RQ-2** | 证据包大小 `K` 对论证质量的影响 | 固定问题，测试 K=5/10/20/30/50 | 审理问题中 `no_evidence` 比例 < 10% |
| **RQ-3** | 正反方 LLM 温度 `temperature` 对论点多样性的影响 | 测试 `t=0.0/0.3/0.7/1.0/1.5` | 论点 unique n-gram 数 × 法官评分一致性 |
| **RQ-4** | 5 位法官之间的评分一致性（IRR - Inter-Rater Reliability） | 计算 Krippendorff's α / Fleiss' Kappa | α ≥ 0.4 为中等一致 |
| **RQ-5** | 真实 LLM vs 人类辩论者的质量差异 | 招募 N=20 人类进行相同问题辩论 + 双盲评分 | 真实 LLM 评分 ≥ 人类 70% |
| **RQ-6** | 不同问题类型（事实性/价值性/政策性）的系统表现差异 | 3 类问题各 10 个，各运行 3 次 | 按类别对比胜率分布 |
| **RQ-7** | 证据来源（arXiv / Crossref / Semantic Scholar）对结论偏置的影响 | 固定问题 × 单一来源 vs 多源混合 | 单一来源时胜率偏差 < 15% |
| **RQ-8** | 推理链长度与结论可靠性的相关性 | 控制推理链节点数 3/5/8/12 | longer chain → 更可靠？ |

### 2.2 可调参数矩阵

| 类别 | 参数名 | 当前默认值 | 测试范围 | 优化方向 |
|------|--------|-----------|---------|---------|
| **Phase 0** | `max_papers`（证据数量） | 20 | 5, 10, 20, 30, 50 | 找出证据-质量拐点 |
| | `sources`（搜索源组合） | 全部启用 | {arXiv}, {Crossref}, {SS}, {全部} | 搜索源对结论偏置 |
| | `keyword_extraction`（关键词策略） | 简单词频 | n-gram / TF-IDF / LLM 抽取 | 召回率 vs 关键词相关性 |
| **Phase 1** | `rounds`（辩论轮数） | 3 | 1, 2, 3, 5, 8 | 边际收益递减点 |
| | `pro_temperature`（正方温度） | 0.7 | 0.0 → 1.5 | 创造力 vs 幻觉率 |
| | `con_temperature`（反方温度） | 0.7 | 0.0 → 1.5 | 同上 |
| | `max_args_per_round`（每轮论点上限） | 2-3 | 1, 2, 3, 5 | 信息密度 vs 冗余 |
| | `model_name`（LLM 模型） | qwen-max | qwen-plus/qwen-max/gpt-4o/claude | 模型规模效应 |
| **Phase 2.1** | `enable_llm_review`（LLM 审理开关） | True | True / False | LLM 审理的增量价值 |
| | `review_temperature`（审理温度） | 0.3 | 0.0, 0.3, 0.7 | 严格 vs 宽松 |
| **Phase 2.2** | `judge_temperature`（法官温度） | 0.5 | 0.0, 0.3, 0.5, 0.7, 1.0 | 法官个体差异控制 |
| | `judge_weights`（法官权重） | 平均 0.2 | 可调权重向量 | 不同问题类型的最优权重 |
| | `winner_threshold`（胜负阈值） | Δscore > 2.0 | 1.0, 2.0, 3.0, 5.0 | 降低平局率但不增加误判 |
| **全局** | `max_tokens`（单次调用 token 上限） | 500-1000 | 200-2000 | 回复长度 vs 成本 |
| | `retry_count`（失败重试次数） | 3 | 1, 3, 5 | 鲁棒性 vs 延迟 |

## 三、实验进化安排

### 实验一：基线测量（Baseline）— v0.3.0
- **目标**：在真实 LLM 下获得各指标的基线值
- **配置**：`qwen-max` / `rounds=3` / `max_papers=20` / `temperature=0.7`
- **问题**：附录 A 全部 12 个问题
- **重复次数**：每问题 3 次（共 36 次完整运行）
- **产出**：
  - 各问题的胜率分布
  - 各法官的平均评分 + 标准差
  - 审理问题数量分布（no_evidence / invalid_cite / weak_support）
  - 总耗时（秒）、总 token 消耗、单次运行成本（元）

### 实验二：参数敏感性扫描（Sensitivity Scan）— v0.4.0
- **目标**：逐一测试 2.2 中每个参数对结果的影响
- **方法**：每次只改变一个参数，其他保持基线值
- **关键输出**：参数-指标敏感性曲线
- **预期发现**：确定 2-3 个对结论影响最大的「关键参数」

### 实验三：系统对比实验（System Comparison）— v0.6.0
- **目标**：在 RQ-1 到 RQ-8 上获得定量数据，用于论文写作
- **对比组**：
  - A. ParaJudge 完整系统
  - B. 单 LLM 直接给出结论（无辩论）
  - C. 人类专家（双盲人工评审）
- **样本量**：12 问题 × 每组 5 次 = 180 次
- **统计检验**：t 检验 / Mann-Whitney U / Wilcoxon signed-rank

### 实验四：消融实验（Ablation Study）— v0.7.0
- **目标**：逐一移除子模块，验证各模块的独立贡献
- **消融项**：
  1. 移除 Phase 2.1 审理模块（不剔除弱论点）
  2. 5 位法官 → 1 位法官（简化裁决）
  3. 移除 Phase 0（不做真实证据检索，使用占位证据）
  4. 固定轮次 vs 自适应终止（KS 检验）
- **预期**：每个消融项都会显著降低裁决质量，证明架构合理性

### 实验五：扩展性测试（Generalization）— v0.9.0
- **目标**：在更广泛问题域中验证系统鲁棒性
- **测试集**：新增 20 个跨领域问题（科学、伦理、历史、技术）
- **外部评估**：邀请 3-5 名研究人员对裁决报告进行 1-5 分评分

## 四、数据记录规范（确保数据真实）

### 4.1 每次运行保存的完整数据结构
```
experiments/
└── run_YYYYMMDD_HHMMSS/
    ├── config.json              # 当前运行的所有参数值
    ├── output.json              # FullPipelineOutput 的完整序列化
    ├── evidence_brief.json      # Phase 0 产物
    ├── transcript.json          # Phase 1 产物
    ├── review_report.json       # Phase 2.1 产物
    ├── judgment_result.json     # Phase 2.2 产物
    ├── llm_calls.log            # LLM 调用日志（prompt / response / tokens / cost）
    ├── render.md                # Markdown 裁决报告
    ├── render.html              # HTML 报告（前端渲染）
    └── metrics.json             # 自动化计算的质量指标
```

### 4.2 每次运行必须记录的元数据
- 版本号（如 `v0.3.0`）
- 时间戳（UTC + 本地）
- 模型名称 + Provider
- API Key 指纹（hash，不保存明文）
- 随机种子（确保可复现）
- 各阶段耗时（ms 级别精度）
- token 使用量（prompt / completion / total）
- 成本估算（元）

### 4.3 质量指标（自动计算）
| 指标 | 含义 | 基线目标 |
|------|------|---------|
| `evidence_coverage` | 论点引用证据的覆盖率 | ≥ 85% |
| `invalid_cite_ratio` | 无效引用占比 | ≤ 5% |
| `judge_agreement` | 法官间 ICC (Intraclass Correlation) | ≥ 0.6 |
| `winner_stability` | 同一问题多次运行的胜负一致率 | ≥ 80% |
| `reasoning_chain_length` | 推理链平均节点数 | ≥ 5 |
| `token_efficiency` | 评分 / 每千元 token | 持续提升 |

## 五、角色清单（用于前端头像）

| 角色 | 阶段 | 身份描述 | 色调 |
|------|------|---------|------|
| 🔍 **证据收集者** Evidence Scout | Phase 0 | 从 arXiv / Crossref / SS 检索学术论文，构建证据包 | 深蓝 |
| ⚖️ **正方辩手** Pro Debater | Phase 1 | 主张问题答案为「是」，提出正面论证 | 绿色 |
| ⚔️ **反方辩手** Con Debater | Phase 1 | 主张问题答案为「否」，提出反面论证 | 红色 |
| 🧐 **审理检察官** Review Prosecutor | Phase 2.1 | 审核论点质量，标记无效引用与弱点 | 紫色 |
| 🧑‍⚖️ **证据法法官** Evidence Judge | Phase 2.2 | 关注证据权威性、相关性和引用规范 | 金色 |
| 🧠 **逻辑分析法官** Logic Judge | Phase 2.2 | 关注论证的逻辑严密性和推理有效性 | 青色 |
| 👑 **原则性法官** Principle Judge | Phase 2.2 | 关注论证的伦理、原则和价值一致性 | 紫色 |
| 📜 **案例法法官** Case Judge | Phase 2.2 | 关注历史案例和经验证据的契合度 | 橙色 |
| 💡 **创新性法官** Innovation Judge | Phase 2.2 | 关注论证中的新颖视角和创造性 | 亮绿 |

共 **9 个角色**，其中 **7 位有独立头像**（2 位辩手 + 5 位法官 + 检察官 + 证据收集者）。
