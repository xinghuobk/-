# ParaJudge 前端设计说明（原型 v0.1）

> 对应文件：`/workspace/frontend_prototype_v0.1.html`
> 在浏览器中直接打开即可预览，无需任何构建工具、无需服务器

---

## 一、设计目标

| 目标 | 说明 |
|------|------|
| 🎯 可视化辩论流程 | 用户能"看到"问题 → 证据 → 辩论 → 审理 → 裁决的全过程 |
| 🎭 角色区分清晰 | 5 类角色（主持人 / 正方 / 反方 / 5 位法官）一眼可辨 |
| 📊 数据可追踪 | 论点 → 引用的证据 → 审理标记 → 裁决推理链，完整闭环可视化 |
| 🎨 动画风格 | 柔和光晕、漂浮头像、气泡发言、脉冲活跃点，有会议厅的温暖氛围 |
| 🖱 交互友好 | 点击阶段按钮跳转、悬停查看证据详情、导出裁决书 |

## 二、视觉系统

### 配色方案
```
主色：
  金色 #FFD700  → 裁决主题、标题、活跃标识
  暖橙 #FF8C42  → 强调色、按钮渐变
  紫红 #FF6B9D  → 点缀

背景：
  深紫渐变 #1A1428 → #2D1B3D → #1F1A2E（营造会议厅氛围）

角色区分：
  正方：蓝绿渐变 #4FACFE → #43E97B（理性、冷静、肯定）
  反方：红橙渐变 #F5576C → #FF8C42（警觉、挑战、质疑）
  主持人：紫粉渐变 #C471F5 → #FA71CD（居中调停）
  法官：每位独立配色（金/蓝紫/粉红/青蓝/青绿）
```

### 头像方案（6 位角色）

| 角色 | Emoji 头像 | 颜色 | 说明 |
|------|-----------|------|------|
| 正方 Agent | 🟢 | 蓝绿渐变 | 理性、论证型 |
| 反方 Agent | 🔴 | 红橙渐变 | 挑战、质疑型 |
| 主持人 | 🎩 | 紫粉渐变 | 居中调停 |
| 证据法法官 | 👨‍⚖️ | 金色 | 看重引用权威性 |
| 逻辑分析法官 | 🧑‍⚖️ | 蓝紫 | 看重论证结构严谨 |
| 原则性法官 | 👩‍⚖️ | 粉红 | 看重伦理/原则 |
| 案例法法官 | 🧑‍⚖️ | 青蓝 | 看重历史案例 |
| 创新性法官 | 👨‍⚖️ | 青绿 | 看重新颖角度 |

**可选项：** 当前使用 Emoji 作为快速原型，确认后可替换为：
- SVG 手绘风格头像（每个角色独特造型 + 微动画眨眼）
- Stable Diffusion 生成的统一风格人像（卡通/写实两种可选）
- 或保持当前的 emoji 风格（零资源消耗，快速加载）

### 动画系统

| 动画 | 用途 |
|------|------|
| `float`（漂浮） | 所有角色头像持续轻柔上下浮动 |
| `glow`（光晕） | 标题、裁决胜者等关键信息的呼吸发光 |
| `pulse`（脉冲点） | 发言中的角色头像右下角绿点 |
| `bubble-in`（气泡入场） | 新发言内容从左侧滑入 |
| `judge-active`（法官活跃） | 正在评分的法官上下轻跳 |
| `ambient`（环境光） | 会议厅背景光晕缓慢呼吸 |

## 六、与后端数据对接

前端需要的核心数据结构（**已与 `schemas.py` 对齐**）：

```typescript
// FullPipelineOutput 对应 schemas.py 中的同名模型
interface ParaJudgeRun {
  run_id: string;
  problem: string;
  evidence_brief: {
    items: EvidenceItem[];    // 证据列表（id/title/authors/year/abstract/...）
    total_count: number;
    query_terms: string[];
  };
  transcript: {
    rounds_total: number;
    arguments: Argument[];     // 论点列表（side/content/evidence_refs）
    argument_index: { pro_count: number; con_count: number };
  };
  review: {
    issues: Issue[];           // 审理问题列表（severity/type/target_arg_id/...）
    critical_count: number;
    warning_count: number;
    pro_issues: number;
    con_issues: number;
    summary: string;
  };
  judgment: {
    winner: "pro" | "con" | "tie";
    pro_final_score: number;    // 0-100
    con_final_score: number;
    judge_scores: JudgeScore[]; // 5 位法官的独立评分
    reasoning_chain_pro: ReasoningNode[];
    reasoning_chain_con: ReasoningNode[];
    uncertainties: string[];
  };
  total_time_sec: number;
}
```

此结构与当前 `backend/models/schemas.py` 中定义 **100% 兼容**，可通过 `model_dump_json()` 直接序列化为前端可消费的 JSON。
