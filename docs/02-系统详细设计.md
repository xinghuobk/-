## 一、系统架构总览

### 1.1 四阶段辩论流程（自顶向下）

```
                      ┌──────────────────────────────────────────┐
                      │   用户问题："LLM 是否会取代人类大部分工作？" │
                      └──────────────────────┬───────────────────┘
                                             ▼
                 ┌─────────────────────────────────────────────────────┐
                 │  Phase 0 · 证据构建器（EvidenceBuilder）              │
                 │  输入：问题文本                                         │
                 │  输出：EvidenceBrief（20-30 篇相关论文 + 相关性评分）    │
                 └──────────────────────┬────────────────────────────────┘
                                        ▼
                ┌─────────────────────────────────────────────────────┐
                │  Phase 1 · 辩论引擎（DebateEngine）                  │
                │  输入：问题 + EvidenceBrief                           │
                │  输出：DebateTranscript（正反方论点 + 引用证据索引）    │
                └──────────────────────┬────────────────────────────────┘
                                       ▼
              ┌─────────────────────────────────────────────────────┐
              │  Phase 2.1 · 审理阶段（ReviewEngine）                │
              │  输入：DebateTranscript                               │
              │  输出：ReviewReport（无效证据检测 + 逻辑漏洞清单）       │
              └──────────────────────┬────────────────────────────────┘
                                     ▼
              ┌─────────────────────────────────────────────────────┐
              │  Phase 2.2 · 裁决引擎（JudgmentEngine）              │
              │  输入：DebateTranscript + ReviewReport                │
              │  输出：JudgmentResult（五维评分 + 推理链 + 判决）        │
              └──────────────────────┬────────────────────────────────┘
                                     ▼
                      ┌──────────────────────────────────┐
                      │  裁决书（HTML / Markdown）         │
                      └──────────────────────────────────┘
```

### 1.2 模块职责边界

| 模块 | 职责 | 不做什么 | 依赖 |
|------|------|----------|------|
| `evidence_builder.py` | 把检索结果包装为 EvidenceBrief，含相关性打分 | 不做事实核查、不做摘要 | `src/search/engine.py:unified_search()` |
| `simple_debate.py` | 正反方 Agent 交替发言，产生结构化论点索引 | 不做交叉质询、不做质量守门 | `llm_client.py`（新）、`prompt_templates.py`（扩展） |
| `review_engine.py` | 扫描论点索引，检测「引用不存在」「证据不支持」「循环论证」等问题 | 不做最终裁决 | `ArgumentIndex` |
| `judgment_engine.py` | 五维法官独立评分 → 加权融合 → 推理链追踪 | 不做内容生成、不润色语言 | `DebateTranscript`, `ReviewReport` |
| `orchestrator.py` | 状态机编排四阶段，收集产出物 | 不实现任何业务逻辑 | 以上所有模块 |
| `llm_client.py` | 统一 LLM 调用封装（替换 `llm_helper.py` 的部分职责） | 不包含 prompt 模板 | provider（openai/dashscope/mock） |

## 二、数据模型设计

> 设计原则：**最小增量**。复用 `schemas.py` 中已有的模型，仅补充必要字段。

### 2.1 需要补充到 `schemas.py` 的模型

```python
# ============================================================
# Phase 0 · 证据构建
# ============================================================

class EvidenceItem(BaseModel):
    """单条证据：一篇论文的摘要 + 相关片段"""
    evidence_id: str                              # E-001, E-002...
    title: str
    authors: List[str] = Field(default_factory=list)
    year: Optional[int] = None
    venue: Optional[str] = None
    abstract_excerpt: str                        # 摘要的前 300 字
    key_quotes: List[str] = Field(default_factory=list)  # 与问题最相关的 1-3 句
    relevance_score: float = Field(default=0.0, ge=0.0, le=1.0)  # 粗略相关性评分
    source_type: str = "academic_paper"          # academic_paper / external_url
    citation_count: Optional[int] = None
    url: Optional[str] = None


class EvidenceBrief(BaseModel):
    """Phase 0 输出：证据摘要包"""
    problem: str
    query_terms: List[str] = Field(default_factory=list)   # 实际用于检索的关键词
    items: List[EvidenceItem] = Field(default_factory=list)
    total_count: int = 0
    build_time_sec: float = 0.0
    generation_time: float = 0.0


# ============================================================
# Phase 1 · 辩论
# ============================================================

class DebateArgument(BaseModel):
    """单个论点（比 schemas.py 中已有 Argument 更具体）"""
    arg_id: str                                  # A-001, A-002...
    content: str                                 # 论点正文
    side: str                                    # "pro" | "con"
    speaker: str                                 # "Pro Agent" / "Con Agent"
    round_index: int                             # 第几次发言（从 1 起）
    evidence_refs: List[str] = Field(default_factory=list)  # 引用的 evidence_id 列表
    reasoning: str = ""                          # Agent 内部推理（可隐藏于裁决书）
    timestamp: float = 0.0


class ArgumentIndex(BaseModel):
    """所有论点的索引（供后续阶段查询）"""
    arguments: List[DebateArgument] = Field(default_factory=list)
    pro_count: int = 0
    con_count: int = 0

    def by_side(self, side: str) -> List[DebateArgument]:
        return [a for a in self.arguments if a.side == side]

    def by_evidence(self, evidence_id: str) -> List[DebateArgument]:
        return [a for a in self.arguments if evidence_id in a.evidence_refs]


class DebateTranscript(BaseModel):
    """Phase 1 完整输出"""
    problem: str
    pro_stance: str
    con_stance: str
    rounds_total: int
    arguments: List[DebateArgument] = Field(default_factory=list)
    argument_index: ArgumentIndex = Field(default_factory=ArgumentIndex)
    generation_time: float = 0.0


# ============================================================
# Phase 2.1 · 审理
# ============================================================

class IssueItem(BaseModel):
    """单个问题项"""
    issue_id: str                               # R-001, R-002...
    severity: str                               # "critical" | "warning" | "info"
    issue_type: str                             # "invalid_cite" / "no_evidence" / "weak_support" / "circular"
    target_arg_id: str                          # 指向哪个论点
    excerpt: str                                # 论点片段
    description: str                            # 问题描述


class ReviewReport(BaseModel):
    """Phase 2.1 审理报告"""
    issues: List[IssueItem] = Field(default_factory=list)
    critical_count: int = 0
    warning_count: int = 0
    pro_issues: int = 0
    con_issues: int = 0
    summary: str = ""
    generation_time: float = 0.0


# ============================================================
# Phase 2.2 · 裁决
# ============================================================

class JudgeScore(BaseModel):
    """单个法官的评分"""
    judge_type: str                             # "evidence" / "logic" / "principle" / "case" / "innovation"
    judge_name: str
    pro_score: float                            # 0-100
    con_score: float                            # 0-100
    pro_feedback: str
    con_feedback: str
    reasoning: str                              # 法官推理过程


class ReasoningNode(BaseModel):
    """推理链节点"""
    node_id: str                                # N-001...
    content: str
    source_type: str                            # "claim" / "evidence" / "intermediate"
    ref_ids: List[str] = Field(default_factory=list)  # arg_id 或 evidence_id


class JudgmentResult(BaseModel):
    """最终裁决结果"""
    winner: str                                 # "pro" | "con" | "tie"
    pro_final_score: float                      # 加权总分
    con_final_score: float
    judge_scores: List[JudgeScore] = Field(default_factory=list)
    reasoning_chain_pro: List[ReasoningNode] = Field(default_factory=list)
    reasoning_chain_con: List[ReasoningNode] = Field(default_factory=list)
    key_points_pro: List[str] = Field(default_factory=list)
    key_points_con: List[str] = Field(default_factory=list)
    uncertainties: List[str] = Field(default_factory=list)
    generation_time: float = 0.0


# ============================================================
# 全流程最终输出
# ============================================================

class FullPipelineOutput(BaseModel):
    """一次完整 ParaJudge 运行的所有产出物"""
    run_id: str
    problem: str
    evidence_brief: EvidenceBrief
    transcript: DebateTranscript
    review: ReviewReport
    judgment: JudgmentResult
    total_time_sec: float
```

### 3.2 Prompt 设计（当前阶段不需要 LLM 参与）

> Phase 0 MVP 版本**不使用 LLM** 做摘要/选择，仅包装检索结果。原因：
> 1. 论文检索本身已经有相关性排序（由 arXiv API relevance 排序）
> 2. LLM 摘要会显著增加 token 成本
> 3. 后续阶段（辩论/裁决）再决定引用哪篇论文

### 3.3 典型输出示例

```json

      "title": "The Economic Potential of Generative AI",
      "authors": ["Brynjolfsson, E.", "et al."],
```

### 3.4 演进路线

| 版本 | 改进点 | 触发条件 |
|------|--------|----------|
| MVP | 直接包装检索结果，启发式打分 | 现在 |
| v1.1 | 用 LLM 从摘要中抽取与问题最相关的 1-2 句话作为 `key_quotes` | Phase 1 跑通后 |
| v1.2 | 让 LLM 判断论文是否支持正方/反方，给每条证据打 `stance_score` | 引入 AEBG 时配合使用 |

## 四、Phase 1 · 极简辩论引擎（SimpleDebate）

### 4.1 模块签名

```python
# src/debate/simple_debate.py

from typing import List
from src.writer.llm_client import LLMClient
from .models_new import (
    EvidenceBrief, DebateTranscript, DebateArgument, ArgumentIndex,
)
from .prompt_templates_debate import (     # 新建 prompt 模板文件
    PROPONENT_PROMPT,
    OPPONENT_PROMPT,
    OUTPUT_FORMAT_PROMPT,
)


class SimpleDebate:
    """
    极简正反方辩论。
    - 每轮：正方发言 → 反方发言
    - 固定轮次（默认 3 轮）
    - 要求 Agent 在发言时必须引用 EvidenceBrief 中的 evidence_id
    - 不做交叉质询、不做 Moderator 守门（阶段 2 再加）
    """

    def __init__(
        self,
        llm: LLMClient,
        rounds: int = 3,
        pro_stance: str = "正方观点：问题的答案为「是」",
        con_stance: str = "反方观点：问题的答案为「否」",
    ):
        self.llm = llm
        self.rounds = rounds
        self.pro_stance = pro_stance
        self.con_stance = con_stance

    def run(
        self,
        problem: str,
        brief: EvidenceBrief,
    ) -> DebateTranscript:
        """
        执行辩论。

        流程：
          for r in 1..rounds:
              pro_arg = self._debater_speak("pro", r, brief, history)
              con_arg = self._debater_speak("con", r, brief, history + [pro_arg])
              history += [pro_arg, con_arg]
          return DebateTranscript(...)
        """
        ...

    # ── 内部方法 ──
    def _debater_speak(
        self,
        side: str,
        round_idx: int,
        brief: EvidenceBrief,
        history: List[DebateArgument],
    ) -> DebateArgument:
        """
        组装 prompt → 调 LLM → 解析输出 → 构造 DebateArgument。
        """
        prompt = self._build_prompt(side, round_idx, brief, history)
        response = self.llm.call(prompt, max_tokens=500, temperature=0.7)
        return self._parse_response(response, side, round_idx)

    def _build_prompt(
        self,
        side: str,
        round_idx: int,
        brief: EvidenceBrief,
        history: List[DebateArgument],
    ) -> str:
        """
        Prompt 结构：
          [角色设定] 你是{立场}的辩论者，必须引用证据包中的 evidence_id。
          [证据包]   以表格形式列出前 15 条 EvidenceItem（id / title / excerpt）。
          [历史]     之前所有发言的简化摘要。
          [任务]     本轮需要提出 2 个论点，每个论点后跟 1-2 条证据引用。
          [格式]     严格 JSON：[{"content": "...", "evidence_refs": ["E-001"]}, ...]
        """
        ...

    def _parse_response(
        self,
        response_text: str,
        side: str,
        round_idx: int,
    ) -> DebateArgument:
        """
        从 LLM 返回的文本中提取 JSON。如果 LLM 未按格式输出，
        回退策略：把整段文本当一个论点，evidence_refs 为空列表。
        """
        ...
```

### 4.3 关键设计决策

| 决策项 | 当前选择 | 理由 | 替代方案 |
|--------|----------|------|----------|
| Agent 数量 | 2 个（正反方） | MVP 最简 | 4 个（每方 2 个，促进内部分歧） |
| 发言策略 | 固定轮次 × 每轮两方 | 简单可控 | KS 检验 + 动态停止（论文创新点，阶段 3 加） |
| 质量守门 | 无 | MVP 不做 | Moderator（阶段 2 加） |
| 输出格式 | 严格 JSON | 便于后续程序解析 | 自然语言 + 后处理（更灵活但更不可靠） |
| 证据引用策略 | 强制引用 evidence_id | 保证可追溯性 | 引用摘要原文而非 id（更自然但不可审计） |

## 五、统一 LLM 调用封装（LLMClient）

### 5.1 为什么不直接用 `AcademicWriter`

- `AcademicWriter` 是为「写作辅助」设计的（summarize/translate/polish/review/outline）
- 辩论场景需要更底层的控制：`max_tokens`, `temperature`, 结构化 JSON 输出
- 需要独立的 mock 策略（返回 mock JSON 而非 mock 段落）
- 论文中的 provider 抽象已足够（openai/dashscope/mock），但我们需要一个**更通用**的调用接口

### 5.2 模块签名

```python
# src/writer/llm_client.py

from __future__ import annotations
import json
import time
from typing import Optional, Any, Dict
from dataclasses import dataclass


@dataclass
class LLMResponse:
    content: str
    model_name: str
    tokens_used: int = 0
    latency_sec: float = 0.0
    raw_response: Any = None


class LLMClient:
    """
    统一 LLM 调用客户端。
    - 支持 provider: "mock" | "openai" | "dashscope"
    - 所有方法最终落到 _call_provider()
    - mock 模式：根据 prompt 特征返回合理的 JSON/文本（不依赖网络）
    """

    def __init__(
        self,
        provider: str = "mock",
        model: str = "mock-model",
        api_key: Optional[str] = None,
    ):
        self.provider = provider.strip().lower()
        self.model = model.strip()
        self.api_key = api_key

    # ── 主接口 ──
    def call(
        self,
        prompt: str,
        max_tokens: int = 500,
        temperature: float = 0.7,
        expect_json: bool = False,
    ) -> str:
        """
        调用 LLM 并返回文本响应。
        - expect_json=True 时，会尝试解析 JSON（失败则回退到提取花括号内容）
        """
        resp = self._call_provider(prompt, max_tokens, temperature)

        if expect_json:
            # 尝试提取最外层的 { ... } 结构
            return self._extract_json(resp.content) or resp.content
        return resp.content

    def call_json(
        self,
        prompt: str,
        max_tokens: int = 500,
        temperature: float = 0.7,
    ) -> Dict[str, Any]:
        """
        期望返回 JSON 的便捷方法。如果解析失败，返回 {"error": "...", "raw": content}。
        """
        text = self.call(prompt, max_tokens, temperature, expect_json=True)
        try:
            return json.loads(text)
        except json.JSONDecodeError:
            # 再试：截取第一个 { 到最后一个 }
            try:
                start = text.index("{")
                end = text.rindex("}") + 1
                return json.loads(text[start:end])
            except (ValueError, json.JSONDecodeError):
                return {"error": "json_parse_failed", "raw": text}

    # ── 内部 ──
    def _call_provider(
        self,
        prompt: str,
        max_tokens: int,
        temperature: float,
    ) -> LLMResponse:
        """根据 provider 分发调用"""
        t0 = time.perf_counter()
        if self.provider == "mock":
            content = self._mock_response(prompt, max_tokens)
        elif self.provider == "openai":
            content = self._openai_call(prompt, max_tokens, temperature)
        elif self.provider == "dashscope":
            content = self._dashscope_call(prompt, max_tokens, temperature)
        else:
            content = f"[unsupported provider: {self.provider}]"
        return LLMResponse(
            content=content,
            model_name=self.model,
            latency_sec=round(time.perf_counter() - t0, 3),
        )

    # ── provider 实现 ──
    def _mock_response(self, prompt: str, max_tokens: int) -> str:
        """
        智能 mock：根据 prompt 关键词决定返回什么。
        - 含 "arguments" + "JSON" → 返回辩论论点 mock JSON
        - 含 "judge" 或 "评分" → 返回裁决评分 mock JSON
        - 含 "review" 或 "审理" → 返回审理问题清单 JSON
        - 其他 → 返回段落文本
        """
        ...  # 具体 mock 数据见实际实现

    def _openai_call(self, prompt: str, max_tokens: int, temperature: float) -> str:
        """
        OpenAI ChatCompletion 调用（或兼容协议，如通义千问的 OpenAI 兼容端点）。
        当前：若未配置 API Key，降级为 mock。
        """
        ...

    def _dashscope_call(self, prompt: str, max_tokens: int, temperature: float) -> str:
        """
        通义千问原生 SDK 调用。
        当前：若未配置 API Key，降级为 mock。
        """
        ...

    @staticmethod
    def _extract_json(text: str) -> Optional[str]:
        """从文本中提取 JSON 结构（用于 LLM 输出解析）"""
        if not text:
            return None
        try:
            start = text.index("{")
            end = text.rindex("}") + 1
            candidate = text[start:end]
            json.loads(candidate)  # 验证
            return candidate
        except (ValueError, json.JSONDecodeError):
            return None
```

## 六、Phase 2.1 · 审理引擎（ReviewEngine）

### 6.1 模块功能

审理阶段的核心目标：**不做裁决，只找问题**。给裁决阶段提供「哪些论点不可靠」的先验信息。

### 6.2 模块签名

```python
# src/judgment/review_engine.py

from typing import List
from src.writer.llm_client import LLMClient
from src.debate.models_new import (
    DebateTranscript, EvidenceBrief, ReviewReport, IssueItem,
)
from .prompt_templates_judgment import REVIEW_PROMPT


class ReviewEngine:
    """
    检察官式审理：扫描所有论点，标记问题。
    检查项：
      1. invalid_cite    — 引用了 evidence_id 不存在的证据
      2. no_evidence     — 完全没有引用任何证据的主张
      3. weak_support    — 引用了证据，但证据内容不直接支持该主张（LLM 判断）
      4. circular        — 循环论证（A 因为 A）
      5. contradiction   — 同一方内部论点矛盾
    """

    def __init__(self, llm: LLMClient):
        self.llm = llm

    def run(self, transcript: DebateTranscript, brief: EvidenceBrief) -> ReviewReport:
        """
        两步审理：
          Step 1. 程序检查（无需 LLM）：
                    扫描所有 arguments，做 invalid_cite 和 no_evidence 检测
          Step 2. LLM 检查：
                    将可疑论点提交 LLM，判断 weak_support / circular / contradiction
        """
        ...

    # ── 程序检查 ──
    def _programmatic_check(
        self,
        transcript: DebateTranscript,
        valid_ids: set,  # 来自 EvidenceBrief 的 evidence_id 集合
    ) -> List[IssueItem]:
        """
        遍历 transcript.arguments：
          - arg.evidence_refs 为空 → no_evidence
          - arg.evidence_refs 中存在 id 不在 valid_ids → invalid_cite
        """
        ...

    # ── LLM 检查 ──
    def _llm_check(
        self,
        transcript: DebateTranscript,
        brief: EvidenceBrief,
    ) -> List[IssueItem]:
        """
        批量提交可疑论点给 LLM，让 LLM 判断：
          - 证据是否真正支持论点（weak_support）
          - 是否存在循环论证（circular）
          - 同一方是否自相矛盾（contradiction）

        Prompt 结构：
          [角色] 你是一名严谨的辩论检察官。
          [证据包] 与辩论阶段相同的 15 条证据。
          [待审论点] 逐条列出。
          [输出] JSON：[{"issue_type": "...", "target_arg_id": "...", "description": "..."}]
        """
        ...
```

### 6.3 审理报告的用途

- 进入裁决阶段时，裁决引擎**会考虑审理报告**
- 被标记为 `invalid_cite` 或 `no_evidence` 的论点在裁决评分时**被降权**
- 裁决书中的 `uncertainties` 字段会列出审理发现的关键问题

**★ 直接写代码**：审理引擎的「程序检查」部分可立即实现（纯逻辑），LLM 检查在 LLMClient 完成后补充。

## 七、Phase 2.2 · 裁决引擎（JudgmentEngine）

### 7.1 MVP 裁决策略（先跑通）

MVP 采用「5 位法官独立评分 + 均等加权」的简单策略。

```python
# src/judgment/judgment_engine.py

from typing import List
from src.writer.llm_client import LLMClient
from src.debate.models_new import DebateTranscript, EvidenceBrief
from .models_new import ReviewReport, JudgmentResult, JudgeScore, ReasoningNode
from .prompt_templates_judgment import (
    EVIDENCE_JUDGE_PROMPT,
    LOGIC_JUDGE_PROMPT,
    PRINCIPLE_JUDGE_PROMPT,
    CASE_JUDGE_PROMPT,
    INNOVATION_JUDGE_PROMPT,
)


class JudgmentEngine:
    """
    MVP 策略：5 位法官独立评分 → 取平均 → 生成裁决。
    每位法官的 prompt 不同（强调的维度不同）。
    """

    JUDGE_TYPES = [
        ("evidence",    "证据法法官",    EVIDENCE_JUDGE_PROMPT),
        ("logic",       "逻辑分析法官",  LOGIC_JUDGE_PROMPT),
        ("principle",   "原则性法官",    PRINCIPLE_JUDGE_PROMPT),
        ("case",        "案例法法官",    CASE_JUDGE_PROMPT),
        ("innovation",  "创新性法官",    INNOVATION_JUDGE_PROMPT),
    ]

    def __init__(self, llm: LLMClient):
        self.llm = llm

    def run(
        self,
        transcript: DebateTranscript,
        brief: EvidenceBrief,
        review: ReviewReport,
    ) -> JudgmentResult:
        """
        1. 为每位法官生成评分
        2. 加权融合（MVP：均等权重）
        3. 生成推理链（从最高评分的论点回溯到证据）
        4. 组装 JudgmentResult
        """
        ...

    # ── 单法官评分 ──
    def _single_judge(
        self,
        judge_type: str,
        judge_name: str,
        prompt_template: str,
        transcript: DebateTranscript,
        brief: EvidenceBrief,
        review: ReviewReport,
    ) -> JudgeScore:
        """
        调用 LLM，让特定类型的法官给出评分和反馈。
        Prompt 注入：
          - 问题
          - 证据包摘要
          - 正反方论点列表（含引用）
          - 审理报告摘要（列出 critical/warning 数量）
          - 法官类型特定的评估标准（如证据法官强调「证据质量与相关性」）

        期望输出 JSON：
          {
            "pro_score": 72,
            "con_score": 65,
            "pro_feedback": "...",
            "con_feedback": "...",
            "reasoning": "..."
          }
        """
        ...

    # ── 加权融合 ──
    @staticmethod
    def _fuse_scores(scores: List[JudgeScore]) -> tuple[float, float]:
        """MVP：简单平均。阶段 3 升级为 DS 证据理论。"""
        pro_total = sum(s.pro_score for s in scores)
        con_total = sum(s.con_score for s in scores)
        return pro_total / len(scores), con_total / len(scores)

    # ── 推理链生成 ──
    def _build_reasoning_chain(
        self,
        side: str,
        scores: List[JudgeScore],
        transcript: DebateTranscript,
    ) -> List[ReasoningNode]:
        """
        简单启发式推理链：
          1. 取该方评分最高的 3 个论点作为「主张节点」
          2. 每个主张节点连接其引用的证据作为「证据节点」
          3. 返回节点列表（裁决书渲染时转化为可视图谱）

        阶段 3：替换为 AEBG 论点-证据二部图算法
        """
```

## 八、主编排器（Orchestrator）

### 8.1 MVP：简单函数链

```python
# src/orchestration/simple_pipeline.py

from __future__ import annotations
import time
import uuid
from dataclasses import dataclass

from src.debate.evidence_builder import build_evidence_brief
from src.debate.simple_debate import SimpleDebate
from src.judgment.review_engine import ReviewEngine
from src.judgment.judgment_engine import JudgmentEngine
from src.writer.llm_client import LLMClient
from .models_new import FullPipelineOutput


def run_parajudge(
    problem: str,
    provider: str = "mock",
    model: str = "mock-model",
    debate_rounds: int = 3,
) -> FullPipelineOutput:
    """
    四阶段串行编排。
    每个阶段的产出物都被保存，便于后续调试/审计。
    """
    t_start = time.perf_counter()
    llm = LLMClient(provider=provider, model=model)

    # Phase 0
    print("[1/4] 构建证据包...")
    brief = build_evidence_brief(problem)
    print(f"      检索到 {brief.total_count} 条证据")

    # Phase 1
    print("[2/4] 正反方辩论...")
    debater = SimpleDebate(llm, rounds=debate_rounds)
    transcript = debater.run(problem, brief)
    print(f"      完成 {transcript.rounds_total} 轮辩论，共 {len(transcript.arguments)} 个论点")

    # Phase 2.1
    print("[3/4] 审理检查...")
    reviewer = ReviewEngine(llm)
    review = reviewer.run(transcript, brief)
    print(f"      发现 {review.critical_count} 个严重问题，{review.warning_count} 个警告")

    # Phase 2.2
    print("[4/4] 法官裁决...")
    judge = JudgmentEngine(llm)
    result = judge.run(transcript, brief, review)
    print(f"      胜方：{result.winner}（正方 {result.pro_final_score:.1f} vs 反方 {result.con_final_score:.1f}）")

    total = round(time.perf_counter() - t_start, 2)
    return FullPipelineOutput(
        run_id=str(uuid.uuid4())[:8],
        problem=problem,
        evidence_brief=brief,
        transcript=transcript,
        review=review,
        judgment=result,
        total_time_sec=total,
    )
```

## 十一、演进路线（从 MVP 到论文系统）

### 阶段 1（当前）：让系统能跑通

- Phase 0 证据构建器（纯程序）

- Moderator（主题漂移检测、重复论点过滤）

- 审理阶段的 LLM 检查（weak_support/circular 检测）
- 裁决书 HTML 渲染（含推理链可视化）

### 阶段 3：引入论文创新点（S3 框架 / AEBG / DPP / KS / DS）

### 阶段 4：生产化

- 成本控制（LLM 调用缓存、prompt 压缩）
- 中文增强（中文检索源、中文 Embedding）

- API 认证与限流
- 审计日志（记录每次运行的完整 prompt/response）

## 十三、关键设计决策汇总

| 决策 | 当前方案 | 理由 | 后续演进 |
|------|----------|------|----------|
| **编排器** | 简单函数链 | 清晰、可调试、无额外依赖 | 阶段 2 引入 LangGraph |
| **辩论策略** | 固定轮次 × 正反各 1 Agent | MVP 最小化 | 阶段 3 用 KS 检验动态停止 + DPP 多样性 |
| **评分融合** | 5 位法官 × 简单平均 | 可解释、易实现 | 阶段 3 升级为 DS 证据理论 |
| **LLM 调用** | 独立 LLMClient（与 AcademicWriter 并行） | 职责分离：写作辅助 ≠ 辩论推理 | 未来抽共享 provider 层 |
| **输出格式** | LLM 强制输出 JSON | 便于程序处理，减少手写解析器 | 保留 JSON，但增加 schema 校验 |
| **证据引用** | evidence_id 引用而非原文 | 可审计、可追溯、节省 token | 阶段 3 引入 AEBG 做结构化分析 |
| **裁决书** | Markdown 文本（MVP） | 可读、可直接保存 | 阶段 2 引入 HTML + 图谱可视化 |
