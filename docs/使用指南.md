# 学术论文工具链 · 使用说明

本项目整合四大功能模块，覆盖一篇研究论文从检索、解析、引用管理到写作辅助的全流程：

- **Search（检索）**：统一入口从 arXiv、Crossref、Semantic Scholar 获取论文元数据
- **Parse（解析）**：解析本地 PDF，提取章节、关键词、参考文献与元数据
- **Reference（引用）**：生成 BibTeX、加载文献库、检索条目、导出 APA / GB/T 7714
- **Write（写作）**：摘要、翻译、润色、大纲、文献综述（支持 OpenAI / DashScope / Mock）

## 安装步骤

### 1. 创建虚拟环境

```bash
python3 -m venv .venv
```

### 2. 激活虚拟环境

- **Linux / macOS / Bash**
  ```bash
  source .venv/bin/activate
  ```
- **Windows (PowerShell)**
  ```powershell
  .venv\Scripts\Activate.ps1
  ```
- **Windows (CMD)**
  ```cmd
  .venv\Scripts\activate.bat
  ```

### 3. 安装依赖

```bash
pip install -r requirements.txt
```

> 如需使用真实 LLM 服务，请在 `.env` 中配置相应 API Key（见下方 *环境变量配置*）。

## CLI 使用示例

所有 CLI 命令统一由 Typer 驱动，入口为 `cli.py`。

```bash
# 查看所有子命令
python3 cli.py --help
```

### 检索

```bash
python3 cli.py search --keyword "retrieval augmented generation" --max-results 10
# 额外通过环境变量控制：
SEARCH_KEYWORD="chain of thought" SEARCH_MAX=5 python3 cli.py search
```

### 解析 PDF

```bash
# 没有 PDF 文件时，脚本内置一份示例文本作为演示
python3 cli.py parse

# 指定本地 PDF
DEMO_PDF_PATH=/path/to/paper.pdf python3 cli.py parse
```

输出将写入 `data/sample_text.txt` 和 `data/parsed_sample.json`。

### 引用管理

```bash
# 默认从演示论文生成 .bib，保存到 data/demo_references.bib
python3 cli.py ref

# 指定检索关键词
REF_KEYWORD="attention" python3 cli.py ref
```

### 写作辅助

```bash
# 使用 Mock Provider，直接跑通全流程（摘要、翻译、润色、大纲、综述、引用格式化）
WRITER_PROVIDER=mock python3 cli.py write

# 使用真实模型（需配置 API Key）
WRITER_PROVIDER=openai WRITER_MODEL=gpt-4o-mini python3 cli.py write
WRITER_PROVIDER=dashscope WRITER_MODEL=qwen-plus python3 cli.py write

# 自定义大纲主题
OUTLINE_TOPIC="Retrieval-Augmented Generation" python3 cli.py write
```

## API 启动示例

使用 FastAPI + Uvicorn 启动 Web API，便于其他服务通过 HTTP 调用。

```bash
# 开发模式（带自动重载）
uvicorn api:app --reload --host 0.0.0.0 --port 8000

# 生产模式
uvicorn api:app --host 0.0.0.0 --port 8000 --workers 2
```

启动后在浏览器访问：

- Swagger UI（推荐）：<http://localhost:8000/docs>
- ReDoc：<http://localhost:8000/redoc>

主要接口：

| 方法 | 路径 | 说明 |
| :--- | :--- | :--- |
| GET  | `/health` | 健康检查 |
| POST | `/search` | 统一检索论文元数据 |
| POST | `/parse` | 解析指定 PDF |
| POST | `/ref/bibtex` | 根据论文元数据生成 BibTeX |
| POST | `/ref/export` | 将 BibTeX 转换为 APA / GB7714 |
| POST | `/write/summarize` | 生成摘要 |
| POST | `/write/translate` | 学术翻译 |
| POST | `/write/polish` | 段落润色 |
| POST | `/write/outline` | 生成论文大纲 |
| POST | `/write/review` | 生成文献综述 |

## Notebook 使用示例

`notebooks/` 下的示例是 **纯 Python 脚本**（非 `.ipynb` JSON），可直接执行，也可在 Jupyter 中通过 `%run` 加载。

- 结果同时以 Rich 表格在终端展示，并以 JSON / `.bib` / `.txt` 形式保存到 `data/` 目录。

**端到端流程推荐先跑**：

`notebooks/` 示例与 `api.py` 均通过环境变量读取敏感配置。

```bash

cp .env.example .env

# 2. 编辑 .env 填入真实 Key（推荐使用 direnv 或手动 source）
```

### `.env.example` 内容速览

```
OPENAI_API_KEY=
DASHSCOPE_API_KEY=
ZOTERO_LIBRARY_ID=
ZOTERO_API_KEY=
```

- **`OPENAI_API_KEY`**：启用 `WRITER_PROVIDER=openai` 时使用。
- **`DASHSCOPE_API_KEY`**：启用 `WRITER_PROVIDER=dashscope`（通义千问）时使用。
- **`ZOTERO_LIBRARY_ID` / `ZOTERO_API_KEY`**：预留的 Zotero 同步入口（可扩展引用导入流程）。

### Notebook 中常用可选变量

```bash
# 检索

SEARCH_MAX=10

# 解析

OUTPUT_DIR=./data

# 写作

# 引用
```

## 常见问题

### Q1. 脚本运行报 `ModuleNotFoundError: No module named 'rich' / 'pymupdf' / ...`

请确认：
1. 已激活虚拟环境 `source .venv/bin/activate`
2. 已运行 `pip install -r requirements.txt`

### Q2. 网络访问受限，搜索 / 写作示例超时

- **检索模块**：会在单个来源失败时静默跳过，若所有来源失败则返回空列表（不会崩溃）。
- **写作模块**：将 `WRITER_PROVIDER=mock`，将使用内置模板化响应，无需网络即可演示。

### Q3. 如何在 Jupyter Notebook 中交互式调用？

```python
import sys
from pathlib import Path
sys.path.insert(0, str(Path(".").resolve()))

from src.search import SearchQuery, SearchSource, unified_search

result = unified_search(
    SearchQuery(
        keyword="retrieval augmented generation",
        max_results=5,
        sources=[SearchSource.ARXIV, SearchSource.CROSSREF],
    )
)
for p in result.papers:
    print(f"- {p.year} | {p.title}")
```

### Q4. PDF 解析失败或结果为空？

- 确认文件存在且非破损版本。
- 扫描件 / 图片版 PDF 需先经过 OCR（可后续接入 `pytesseract` 或商用 OCR 服务）。
- 内置 fallback 示例文本路径：在未提供 `DEMO_PDF_PATH` 时，脚本会使用内置示例。

### Q5. 写作模块想接入自定义 LLM Provider？

在 `src/writer/llm_helper.py` 中：
1. 扩展 `_call_llm()`，根据 `self.provider` 分发到对应 SDK。
2. 在 `.env` 中新增对应 API Key，由 `AcademicWriter.__init__` 通过 `os.environ` 读取。

### Q6. 如何验证脚本语法？

```bash
# 单文件
python3 -m py_compile notebooks/01_search_demo.py

# 批量
for f in notebooks/*.py; do python3 -m py_compile "$f" && echo "OK: $f"; done
```

`py_compile` 仅执行语法检查，不运行脚本。若所有文件通过，则不会打印任何错误。

### Q7. 输出文件保存在哪里？

默认写入 `data/` 目录（若不存在则自动创建），可通过环境变量 `OUTPUT_DIR` 覆盖。常见产物：

- `data/search_result.json`
- `data/sample_text.txt` + `data/parsed_sample.json`
- `data/demo_references.bib`
- `data/writing_demo_output.json`
- `data/end_to_end_output.json` + `data/end_to_end_references.bib`

### Q8. 为什么使用 `.py` 而不是 `.ipynb` 作为 Notebook 示例？

- `.ipynb` 本质是 JSON，手写易错且不易于代码审查。
- 纯 Python 脚本可以：直接 `python` 执行、在 Jupyter 中通过 `%run` 加载、使用常规 Git diff。
- 如需转为 Jupyter Notebook，可使用 `jupytext`、`p2j` 等工具一键转换。
