## 一、原型机编号系统

采用 **「阶段 · 内部版本 · 模型版本 · 数据集版本」** 四段式语义化编号。

```
v[阶段].[内部版本].[模型版本].[数据集版本]
  │      │          │          └── 证据包 / 题目集 版本
  │      │          └──  LLM 提供商 / 具体模型
  │      └── 系统代码内部迭代（bugfix、功能变更）
  └── 阶段（0=MVP 开发期 / 1=实验期 / 2=论文期 / 3=发布期）
```

### 当前版本基准线

| 编号 | 版本号 | 说明 | 对应代码 commit |
|------|--------|------|----------------|
| **v0.1.0.0** | `v0.1.0.0` | 首个可运行 MVP（mock LLM，65 测试通过，Phase 0/1/2 全链路） | 当前 HEAD |
| **v0.2.x.x** | `v0.2.x.x` | 接入真实 LLM（OpenAI GPT-4o / DashScope Qwen-Max） | 待开发 |
| **v0.3.x.x** | `v0.3.x.x` | 加入主持人角色（Moderator）+ 收敛检测 | 待开发 |
| **v1.0.0.0** | `v1.0.0.0` | 实验基准版（所有参数冻结，用于主实验） | 待冻结 |

### 版本号变更规则

- **阶段位**：只有在进入新的生命周期阶段时才升级（MVP → 实验 → 论文 → 发布）
- **内部版本**：代码结构变化、新功能加入（如加入 T1 AEBG、T2 DPP、主持人等）
- **模型版本**：更换 LLM 提供商或具体模型名（gpt-4o → gpt-5、qwen-max → qwen-plus）
- **数据集版本**：新增/修改辩论题目集，或证据包的检索源配置变更

### 实验运行日志编号

每一次完整运行的唯一标识格式：

```
RUN-[日期]-[4 位序号]-[版本号]
示例：RUN-20260617-0001-v0.1.0.0
```

每次运行自动归档：
- `logs/[RUN_ID]/console_output.log` —— 控制台输出
- `logs/[RUN_ID]/result.json` —— 结构化 FullPipelineOutput
- `logs/[RUN_ID]/report.md` —— Markdown 裁决书
- `logs/[RUN_ID]/config.json` —— 本次使用的所有参数配置

## 二、需要通过实验研究确定的问题

（按"可验证 + 可量化 + 对系统影响程度"排序，**所有数据必须来自真实 LLM 运行结果**）

### 第一类：核心机制类（必须做实验）

| # | 研究问题 | 假设（H₀ / H₁） | 指标 | 实验次数 |
|---|---------|----------------|------|---------|
| RQ-01 | **辩论轮次 (R) 对裁决稳定性的影响** | H₀：R=3 与 R=5 的 winner 差异 ≤ 10%；H₁：增加轮次显著改变结果 | 胜方一致率、评分标准差、法官分歧度 | 每个 R 值 × 20 个问题 = 60 次 |
| RQ-02 | **证据包大小 (N) 对论证质量的影响** | H₀：N=10 与 N=30 的证据引用质量无差异；H₁：更多证据 = 更少 invalid_cite | no_evidence 率、invalid_cite 率、关键论点引用数 | N∈{5,10,20,30,50} × 10 问题 = 50 次 |
| RQ-03 | **5 位法官权重分配是否合理** | H₀：平权 (×1/×1/×1/×1/×1) 最优；H₁：某一法官权重应下调 | 与人工评分的 Pearson 相关系数 r | 20 题 × 3 组权重 = 60 次 |
| RQ-04 | **正反方发言顺序是否引入偏见** | H₀：先正方 vs 先反方，胜方比例无显著偏差；H₁：存在首发言优势 | 正方胜率在两种顺序下的 χ² 检验 | 20 题 × 2 顺序 × 2 次（交换重跑） = 80 次 |
| RQ-05 | **LLM 模型选择对结果的影响** | H₀：GPT-4o vs Qwen-Max 裁决一致率 ≥ 70%；H₁：模型选择是最大误差源 | 胜方一致率、评分差均值 | 10 题 × 3 模型（+1 Claude 可选） = 30 次 |
| RQ-06 | **Temperature 参数对辩论多样性的影响** | H₀：T=0.2 与 T=1.0 的论点重复率差 < 15%；H₁：低 T 导致重复论证 | 论点 Jaccard 相似度、法官对"创新性"评分 | T∈{0.2, 0.5, 0.7, 1.0} × 10 题 = 40 次 |

### 第二类：算法创新类（T1/T2/T3/T4 的验证）

| # | 研究问题 | 指标 | 实验规模 |
|---|---------|------|---------|
| RQ-07 | **AEBG（论证-证据二部图）能否量化论证质量** | AEBG PageRank 分 vs 人工评分的 Spearman 相关系数 | 30 次辩论 |
| RQ-08 | **DPP 多样性约束是否真的提升了裁决质量** | 有/无 DPP 对比实验，Δ(uncertainties 数量)、Δ(winner 一致率) | 配对实验：20 题 × 2 条件 = 40 次 |
| RQ-09 | **KS 检验收敛检测能否减少冗余轮次** | 实际需要的轮次 vs 固定 R=5 的节省比例、提前终止时裁决一致性 | 30 题，记录每轮后的 KS 统计量 |
| RQ-10 | **Dempster-Shafer 证据融合 vs 简单加权平均** | 与人工基准的 MAE、冲突 mass 分布 | 30 次对比 |

### 第三类：人机对齐类（需要人工标注员）

| # | 研究问题 | 指标 | 所需资源 |
|---|---------|------|---------|
| RQ-11 | **ParaJudge 裁决 vs 人工专家裁决的一致率** | Cohen's κ、胜方准确率 | 至少 3 位独立标注员 × 30 题 = 90 份人工标注 |
| RQ-12 | **ParaJudge 识别 invalid_cite 的精确率/召回率** | Precision / Recall / F1 | 人工检查 100 个论点的引用合法性 |
| RQ-13 | **裁决书的可读性**（用于论文呈现） | 标注员对 5 分制 Likert 量表的平均评分 | 20 份裁决书 × 3 标注员 |

### 第四类：成本与性能类

| # | 研究问题 | 指标 |
|---|---------|------|
| RQ-14 | **每次辩论的平均 token 消耗与成本** | tokens 总量（分阶段统计）、美元成本 |
| RQ-15 | **延迟分析**：Phase 0/1/2 各阶段耗时 | 各阶段时间分布箱线图 |
| RQ-16 | **复现性**：完全相同输入（固定 seed）两次运行的结果一致率 | winner 一致率、评分差 |

## 三、系统参数矩阵

### 3.1 Phase 0 · 证据构建参数

| 参数名 | 当前值 | 实验范围 | 说明 | 影响方向（假设） |
|--------|--------|---------|------|-----------------|
| `max_papers` | **20** | 5 / 10 / 20 / 30 / 50 | 证据包中的论文上限 | 增加 → 引用率↑、成本↑↑ |
| `keyword_extraction_strategy` | **启发式 (Rake-like)** | 启发式 / LLM 抽取 | 关键词生成方式 | LLM 方式更精准但多 1 次 API 调用 |
| `min_keyword_length` | **2** | 2 / 3 / 4 | 关键词最短字符数 | 提高 → 关键词更精，但可能丢失长尾 |
| `relevance_threshold` | **0.0**（全保留） | 0.0 / 0.3 / 0.5 | 证据相关性过滤阈值 | 提高 → 证据更聚焦，但可能丢失论据 |
| `search_sources` | **[arXiv, Crossref, Semantic Scholar]** | 3 种组合 | 搜索引擎启用列表 | Semantic Scholar 可能带来更多引用数据 |
| `year_min` | **None** | None / 2018 / 2020 | 最早出版年份限制 | 提高 → 更新颖但更少证据 |

### 3.2 Phase 1 · 辩论参数

| 参数名 | 当前值 | 实验范围 | 说明 | 影响方向 |
|--------|--------|---------|------|---------|
| `rounds` | **3** | 1 / 2 / 3 / 5 / 7 | 辩论轮数（每轮 = 正方 + 反方各一次发言） | 增加 → 信息更充分、成本↑、不确定性↓ |
| `max_args_per_speaker` | **3** | 1 / 2 / 3 / 5 | 单次发言最多生成的论点数 | 影响论证密度 |
| `temperature` | **0.7** | 0.2 / 0.5 / 0.7 / 1.0 | LLM 温度参数 | 提高 → 更有创造性但更不稳定 |
| `max_tokens_per_prompt` | **800** | 500 / 800 / 1200 / 2000 | 单次发言的 token 上限 | 影响论证长度 |
| `enable_history_injection` | **True** | True / False | 是否将对方历史论点注入当前 prompt | False → 各自独立论证、无交叉质询 |
| `first_speaker` | **"pro"** | pro / con / random | 固定或随机先发言方 | 先发言可能有锚定效应 |
| `max_items_in_prompt` | **15** | 5 / 10 / 15 / 20 | 每个 LLM prompt 注入的证据条数 | 影响可引用范围 |

### 3.3 Phase 2.1 · 审理参数

| 参数名 | 当前值 | 实验范围 | 说明 |
|--------|--------|---------|------|
| `enable_programmatic_check` | **True** | True | 启用程序化检查（no_evidence / invalid_cite） |
| `enable_llm_check` | **True** | True / False | 启用 LLM 检查（weak_support / contradiction） |
| `llm_check_temperature` | **0.3** | 0.1–0.5 | 审理专用 LLM 温度 |
| `severity_threshold_critical` | **"invalid_cite"** | 可配置 | 哪些 issue 类型视为严重 |
| `critical_issue_auto_penalty` | **扣 5 分** | 0 / 5 / 10 / 20 | 每个 critical issue 对法官评分的扣分 |

### 3.4 Phase 2.2 · 裁决参数

| 参数名 | 当前值 | 实验范围 | 说明 |
|--------|--------|---------|------|
| `judge_types` | **[证据法, 逻辑, 原则性, 案例法, 创新性]** | 可增减类型 | 法官类型集合 |
| `judge_weights` | **[1, 1, 1, 1, 1]** | 3 组实验权重 | 5 位法官加权系数 |
| `winner_threshold` | **> 2.0 分差** | 1.0 / 2.0 / 5.0 | 判定胜方的最小分差 |
| `reasoning_chain_max_nodes` | **6** | 3 / 6 / 10 | 推理链最大节点数 |
| `fusion_method` | **"mean"** | mean / median / DS | 融合策略（DS = Dempster-Shafer） |

### 3.5 LLM 模型参数

| 参数 | 当前值 | 可选值 | 说明 |
|------|--------|--------|------|
| `provider` | **mock** | mock / openai / dashscope / anthropic | API 提供商 |
| `model_name` | **mock-model** | gpt-4o / gpt-4o-mini / qwen-max / qwen-plus / claude-sonnet | 具体模型 |
| `seed` | **None** | None / 42 / 固定整数 | 用于可复现实验 |
| `api_key` | **环境变量** | — | 通过 `OPENAI_API_KEY` / `DASHSCOPE_API_KEY` 注入 |

## 四、实验进化路线（8 个实验阶段）

### 总实验预算建议：约 300 次独立辩论运行 ≈ $50–$150（GPT-4o-mini / Qwen-Plus 级别）

### 阶段实验一览

| 阶段 | 编号 | 目标 | 核心实验 | 冻结参数 | 变动参数 | 预计运行次数 |
|------|------|------|---------|---------|---------|-------------|
| 🟢 校准 | **EXP-000** | 建立基线 | 用 v0.1.0.0 跑 20 题（题目取自 Appendix A），建立各指标基准分布 | 全默认 | 无 | 20 |
| 🔵 轮次 | **EXP-001** | RQ-01：确定最佳辩论轮次 | rounds ∈ {1, 2, 3, 5, 7}，每个值 × 20 题 | 其他全默认 | rounds | 100 |
| 🔵 证据 | **EXP-002** | RQ-02：确定证据包规模 | max_papers ∈ {5, 10, 20, 30, 50}，每个 × 10 题 | rounds=最佳值 | max_papers | 50 |
| 🔵 权重 | **EXP-003** | RQ-03：优化法官权重 | 3 组权重方案 × 20 题对比人工标注 | rounds, max_papers | judge_weights | 60 |
| 🔵 偏见 | **EXP-004** | RQ-04：发言顺序偏见检验 | 20 题 × 2 种顺序 + 交换重跑 | rounds, max_papers, weights | first_speaker | 80 |
| 🟡 模型 | **EXP-005** | RQ-05：跨模型一致性 | 3 种 LLM × 10 题 | 其他全优化后 | provider + model | 30 |
| 🟡 温度 | **EXP-006** | RQ-06：温度对多样性的影响 | T ∈ {0.2, 0.5, 0.7, 1.0} × 10 题 | 其他全优化后 | temperature | 40 |
| 🟠 算法 | **EXP-007** | RQ-07~RQ-10：T1–T4 创新点验证 | 对照实验（有/无 AEBG、DPP、KS、DS）× 20 题 | 基础参数全部冻结 | T1/T2/T3/T4 开关 | 40+ |
| 🔴 人机 | **EXP-008** | RQ-11~RQ-13：人工基准对齐 | 30 题 × 3 位标注员 | 所有算法参数 | 人工标注 | 30 |
| 🟣 复现 | **EXP-009** | RQ-14~RQ-16：成本/延迟/复现性 | 固定 seed 重跑 30 题 2 次 | seed | — | 60 |

### 基准问题集（Appendix A，20+ 题）

作为 EXP-000 的输入，题目覆盖以下 5 个维度 × 每维度至少 4 题：

1. **技术事实类**（例：「量子计算能在 10 年内破解 RSA-2048 吗？」）
2. **社会影响类**（例：「LLM 是否会取代人类大部分工作？」）
3. **政策争议类**（例：「应对 AI 生成内容强制加水印吗？」）
4. **伦理判断类**（例：「应赋予高级 AI 某种形式的法律人格吗？」）
5. **科研方法类**（例：「LLM 应作为论文共同作者署名吗？」）

每个问题同时给出「预期正方应胜出」「预期反方应胜出」「预期平局」三种标签，用于计算 ParaJudge 的准确率。
